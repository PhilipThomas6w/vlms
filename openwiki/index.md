# VLMS codebase wiki (openwiki)

Agent-native reference for the current state of the code, refreshed as the codebase changes (`loop-harness:doc-refresh`). This describes what is actually built, not the design intent — for design intent and rationale, read `docs/` (requirements, design, ADRs) and `docs/VISION.md` first.

Read order for a new session: `docs/VISION.md` → `STATE.md` → this index → the specific page(s) below relevant to the task.

## Pages

- [architecture.md](architecture.md) — solution shape, project dependency graph, where each concern lives.
- [domain.md](domain.md) — `Vlms.Domain`: entities, the `Role` enum, `ICurrentUserContext`.
- [data-access.md](data-access.md) — `Vlms.Infrastructure`: `VlmsDbContext`, EF Core configuration, migrations.
- [access-control.md](access-control.md) — the ADR-0004 sensitive-data mechanism: query filters + read-audit interceptor. Read this before touching anything near `DbsCheck`/`ConsentSensitiveDetails`/`SensitiveDataAccessLog`.

- [web.md](web.md) — `Vlms.Web`: `Program.cs` wiring, Blazor Server interactive render mode, `AuthorizeRouteView`-based page gating, and the PWA manifest/service worker (installability, scoped to a Server-interactive app — no offline app execution).

- [guardian-links.md](guardian-links.md) — `GuardianLinkService` (FR-004: Admin/Teacher-only `StudentGuardianLink` creation, never parent self-service), the new `AnyRoleRequirement`/`AnyRoleAuthorizationHandler` authorization mechanism, and the guardian-links page.
- [student-registration.md](student-registration.md) — `StudentRegistrationService`: creates the `Student` record, opens their first `StudentRankProgress` row at the starting rank, and creates a guardian link via `GuardianLinkService`. Closes `PromotionService`'s "no open StudentRankProgress row" precondition.
- [safeguarding-consent.md](safeguarding-consent.md) — `ConsentRecordService`/`DbsCheckService` (consent/DBS management UI), the daily `ConsentExpiryJob` sweep (expiry/DBS flagging, 8-week at-risk/disengagement flagging, log-based escalation plus real notifications — see below), `SystemCurrentUserContext`, and the `Vlms.Jobs` host project — scheduled via a systemd timer (`deploy/systemd/`) since adr/0005's hosting pivot, not the original Azure WebJob.
- [notifications.md](notifications.md) — `INotificationService`/`NotificationService` (SMTP via MailKit, adr/0005 — retry/escalation for safeguarding-critical notifications) and `ConsentExpiryNotifier`, which translates `ConsentExpiryJob`'s output into real emails.
- [parent-dashboard.md](parent-dashboard.md) — `ParentDashboardService` and the `/parent/dashboard` page: a Parent's own linked students' progress/badges/certificates/consent status, scoped via the new shared `ParentGuardianLinkage` helper.

Also `RecordsDueForDeletionService`/`RetentionFlagging` and the `/reporting/records-due-for-deletion` page (Admin-only) — the "records due for deletion" retention report — plus `Retention.LeavingService` and the `/retention/mark-as-left` page (Admin-only), which closed the report's original "no leaving date recorded anywhere" schema gap: `Student.LeftAt`/`AppUser.HasLeft`/`AppUser.LeftAt` now let Inactive students and left Teachers be flagged too, not just Graduated students and DBS-expiry.
- [testing.md](testing.md) — test conventions: the SQLite-in-memory pattern, `FakeCurrentUserContext`, what "real, not tautological" means in this repo's tests.
- [verify-gate.md](verify-gate.md) — `build/verify.ps1`'s full-only stages: the ASVS 5.0 V8 access-control review and the WCAG 2.2 AA accessibility check, their static-scan checks, and the content-hash mechanism that keeps their paired manual-review checklists honest.

## Current build state (as of this refresh)

The MVP feature set from `docs/VISION.md`'s current increment is built: the EF Core data model + ADR-0004 access control, authentication/authorization (now self-rolled ASP.NET Core Identity with TOTP MFA — see below), curriculum management, progress tracking (now including the Teacher-facing completion-reversal flow — see below), guardian-link creation + student registration/enrolment, safeguarding & consent (+ the `ConsentExpiryJob` WebJob), the parent dashboard + `NotificationService`, Admin reporting, and a PWA manifest/service worker for installability. `Vlms.Web/Components/Pages/` has real VLMS UI for all of it (`Home.razor`, `Curriculum/`, `Guardianship/`, `Registration/`, `Safeguarding/`, `Parent/`, `Reporting/`, `Progress/`) plus the Identity/Account surface under `Components/Account/Pages/`. Full per-item history, commit SHAs, and gate evidence live in `STATE.md`'s `## Done` section — this index doesn't restate it.

**Two provider/hosting pivots since the original design gate, both per `docs/adr/0005-hosting-pivot-self-hosted-vps-postgresql.md`** (moving from the original Azure App Service/Azure SQL/Entra External ID design to a self-hosted VPS): (1) the EF Core provider moved from Azure SQL Database to self-hosted PostgreSQL (`UseNpgsql`, snake_case naming convention, the `REVOKE`-based tamper-protection port — see [access-control.md](access-control.md)); (2) **STATE.md's "Identity" item replaced Microsoft Entra External ID with self-rolled ASP.NET Core Identity (TOTP MFA)**, and replaced the Microsoft Graph guardian-invitation mechanism with a self-rolled signed/single-use/expiring invite link — see [authentication-authorization.md](authentication-authorization.md) and [guardian-links.md](guardian-links.md). This retired (not just unblocked) the former `## Blocked / needs decision` live-Entra-tenant item.

**A third and fourth pivot item have now landed:** `AzureBlobStorage` was replaced with `LocalDiskBlobStorage` (`src/Vlms.Infrastructure/Storage/`) — certificates/lesson assets now write to the self-hosted VPS's own filesystem instead of Azure Blob Storage; see [progress-tracking.md](progress-tracking.md). `AzureCommunicationEmailSender` was replaced with `SmtpEmailSender` (`src/Vlms.Infrastructure/Notifications/`, backed by MailKit — verified against Microsoft's own guidance that the built-in `System.Net.Mail.SmtpClient` is obsolete) — see [notifications.md](notifications.md). **A fifth and sixth pivot item have now also landed:** `Vlms.Jobs` was retargeted from the Azure WebJobs folder convention to a systemd timer/service pair (`deploy/systemd/vlms-jobs.*`), and the full deployment-scripting item now exists — `deploy/Caddyfile` (Kestrel behind Caddy, automatic HTTPS), `deploy/systemd/vlms-web.service` (`Vlms.Web`'s Kestrel process), `deploy/postgres/` (least-privilege `vlms_app` role vs. schema-owning `vlms_owner`, `governance/raid.md` D-004), and `deploy/backup/` (`pg_dump` shipped to an S3-compatible bucket, provider still undecided) — script/config only, no real VPS provisioned without Philip's explicit go-ahead; see [architecture.md](architecture.md)'s "Hosting/deployment" section and `deploy/README.md`. **The Teacher-facing completion-reversal flow has now landed** (STATE.md — `CompletionService.ReverseAsync`, the `/progress/completions` page): `IsReversed`/`ReversedAt` are now genuinely set by a real write path, not just test seed data, closing the gap this paragraph used to name here. See [progress-tracking.md](progress-tracking.md) for the scope decisions (own-entry-only scoping, the 7-day default reversal window, the optional-note merge behaviour, and the explicit no-cascade-to-past-promotions decision) and [parent-dashboard.md](parent-dashboard.md) for how this closed the loop on that page's certificate-visibility decision. **The "records due for deletion" report has now landed** (STATE.md — `RecordsDueForDeletionService`/`RetentionFlagging`, the `/reporting/records-due-for-deletion` page): the interim retention-enforcement mechanism data-design.md named, widening `ConsentExpiryJob`'s daily sweep per its own "from ConsentExpiryJob's wider sweep" wording. **The "no leaving date recorded anywhere" schema gap that report originally surfaced has since been closed**, per Philip's decision (2026-08-12): a manual, Admin-only `Retention.LeavingService` (`/retention/mark-as-left`) sets `Student.LeftAt`/`AppUser.HasLeft`/`AppUser.LeftAt` (auto-captured at the moment the action runs, never backdated), and `RetentionFlagging` now uses them — Inactive students and left Teachers are genuinely flaggable, not just Graduated students and DBS-expiry. See [admin-reporting.md](admin-reporting.md) for the full detail. Since this refresh's prior state, four small WCAG accessibility fixes have also landed (form-page status messages via `role="status"`, `MainLayout.razor`'s error-banner dismiss control converted from an unfocusable `<span>` to a real `<button>`, and `role="alert"` added to `<ValidationSummary />`/framework error surfaces missing it) — none change any architecture or mechanism this wiki describes, so no other page needed updating for them. `## Blocked / needs decision` is currently empty.
