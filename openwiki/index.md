# VLMS codebase wiki (openwiki)

Agent-native reference for the current state of the code, refreshed as the codebase changes (`loop-harness:doc-refresh`). This describes what is actually built, not the design intent — for design intent and rationale, read `docs/` (requirements, design, ADRs) and `docs/VISION.md` first.

Read order for a new session: `docs/VISION.md` → `STATE.md` → this index → the specific page(s) below relevant to the task.

## Pages

- [architecture.md](architecture.md) — solution shape, project dependency graph, where each concern lives.
- [domain.md](domain.md) — `Vlms.Domain`: entities, the `Role` enum, `ICurrentUserContext`.
- [data-access.md](data-access.md) — `Vlms.Infrastructure`: `VlmsDbContext`, EF Core configuration, migrations.
- [access-control.md](access-control.md) — the ADR-0004 sensitive-data mechanism: query filters + read-audit interceptor. Read this before touching anything near `DbsCheck`/`ConsentSensitiveDetails`/`SensitiveDataAccessLog`.
- [authentication-authorization.md](authentication-authorization.md) — self-rolled ASP.NET Core Identity sign-in with TOTP MFA (originally Microsoft Entra External ID, replaced by STATE.md's "Identity" item), the `AppUser`/`VlmsIdentityUser` coexistence design, `AppUser`/`UserRole` provisioning, role- and resource-based authorization, MFA enforcement, and how the caller's `ClaimsPrincipal` is resolved for interactive Blazor Server components.
- [web.md](web.md) — `Vlms.Web`: `Program.cs` wiring, Blazor Server interactive render mode, `AuthorizeRouteView`-based page gating, and the PWA manifest/service worker (installability, scoped to a Server-interactive app — no offline app execution).
- [curriculum.md](curriculum.md) — `LessonProposalService` (propose/approve/reject/resubmit) and the Teacher/Approver pages.
- [progress-tracking.md](progress-tracking.md) — `CompletionService`/`PromotionService`/`CertificateService`, the `IBlobStorage` abstraction, and the auto-promotion rank-ladder logic.
- [guardian-links.md](guardian-links.md) — `GuardianLinkService` (FR-004: Admin/Teacher-only `StudentGuardianLink` creation, never parent self-service), the new `AnyRoleRequirement`/`AnyRoleAuthorizationHandler` authorization mechanism, and the guardian-links page.
- [student-registration.md](student-registration.md) — `StudentRegistrationService`: creates the `Student` record, opens their first `StudentRankProgress` row at the starting rank, and creates a guardian link via `GuardianLinkService`. Closes `PromotionService`'s "no open StudentRankProgress row" precondition.
- [safeguarding-consent.md](safeguarding-consent.md) — `ConsentRecordService`/`DbsCheckService` (consent/DBS management UI), the `ConsentExpiryJob` WebJob (expiry/DBS flagging, 8-week at-risk/disengagement flagging, log-based escalation plus real notifications — see below), `SystemCurrentUserContext`, and the `Vlms.Jobs` WebJob host project.
- [notifications.md](notifications.md) — `INotificationService`/`NotificationService` (Azure Communication Services Email, retry/escalation for safeguarding-critical notifications) and `ConsentExpiryNotifier`, which translates `ConsentExpiryJob`'s output into real emails.
- [parent-dashboard.md](parent-dashboard.md) — `ParentDashboardService` and the `/parent/dashboard` page: a Parent's own linked students' progress/badges/certificates/consent status, scoped via the new shared `ParentGuardianLinkage` helper.
- [admin-reporting.md](admin-reporting.md) — `ProgressReportingService` (core progress stats: rank/status counts, completion total, promotion history) and the `/reporting` page (Admin-only), plus `AtRiskStudentFlagging` — the 8-week disengagement computation extracted out of `ConsentExpiryJob` so both the WebJob and this on-demand screen share one implementation.
- [testing.md](testing.md) — test conventions: the SQLite-in-memory pattern, `FakeCurrentUserContext`, what "real, not tautological" means in this repo's tests.
- [verify-gate.md](verify-gate.md) — `build/verify.ps1`'s full-only stages: the ASVS 5.0 V8 access-control review and the WCAG 2.2 AA accessibility check, their static-scan checks, and the content-hash mechanism that keeps their paired manual-review checklists honest.

## Current build state (as of this refresh)

The MVP feature set from `docs/VISION.md`'s current increment is built: the EF Core data model + ADR-0004 access control, authentication/authorization (now self-rolled ASP.NET Core Identity with TOTP MFA — see below), curriculum management, progress tracking, guardian-link creation + student registration/enrolment, safeguarding & consent (+ the `ConsentExpiryJob` WebJob), the parent dashboard + `NotificationService`, Admin reporting, and a PWA manifest/service worker for installability. `Vlms.Web/Components/Pages/` has real VLMS UI for all of it (`Home.razor`, `Curriculum/`, `Guardianship/`, `Registration/`, `Safeguarding/`, `Parent/`, `Reporting/`) plus the Identity/Account surface under `Components/Account/Pages/`; progress tracking still has no consuming page for `CompletionService`/`PromotionService`/`CertificateService` directly (service-layer only). Full per-item history, commit SHAs, and gate evidence live in `STATE.md`'s `## Done` section — this index doesn't restate it.

**Two provider/hosting pivots since the original design gate, both per `docs/adr/0005-hosting-pivot-self-hosted-vps-postgresql.md`** (moving from the original Azure App Service/Azure SQL/Entra External ID design to a self-hosted VPS): (1) the EF Core provider moved from Azure SQL Database to self-hosted PostgreSQL (`UseNpgsql`, snake_case naming convention, the `REVOKE`-based tamper-protection port — see [access-control.md](access-control.md)); (2) **STATE.md's "Identity" item replaced Microsoft Entra External ID with self-rolled ASP.NET Core Identity (TOTP MFA)**, and replaced the Microsoft Graph guardian-invitation mechanism with a self-rolled signed/single-use/expiring invite link — see [authentication-authorization.md](authentication-authorization.md) and [guardian-links.md](guardian-links.md). This retired (not just unblocked) the former `## Blocked / needs decision` live-Entra-tenant item.

`STATE.md`'s `## Next` queue is the rest of the hosting pivot, ordered by dependency: replacing `AzureBlobStorage`/`AzureCommunicationEmailSender` with local-disk/SMTP-based implementations, retargeting `Vlms.Jobs` from the Azure WebJobs folder convention to a systemd timer, deployment scripting (Caddy/systemd/PostgreSQL/backups — script-only, no real VPS provisioned without Philip's explicit go-ahead), a `build/verify.ps1`/secrets-scan currency pass, and a security-relevant Row-Level-Security hardening follow-up for `SensitiveDataAccessLog`'s tamper protection (found during the PostgreSQL migration — the `REVOKE`-based protection is verified weaker than the SQL Server `DENY` it replaced; see [access-control.md](access-control.md)). `## Blocked / needs decision` is currently empty. One unrelated lower-priority item is also queued: a Teacher-facing "reverse a completion" flow doesn't exist yet, despite `IsReversed`/`ReversedAt` being read throughout the codebase.
