# Curriculum management

Design source: `docs/requirements/functional.md` FR-007, `docs/adr/0013-lesson-suggestions-review-and-history.md` (which replaced the earlier propose/approve/reject proposal workflow and its pages, removed with migration `AddLessonSuggestionsAndVersions`).

## Lesson suggestions, review and history (`LessonSuggestionService`, `src/Vlms.Infrastructure/Curriculum/`)

- **Data** (migration `20261026201439_AddLessonSuggestionsAndVersions`, which also drops `lesson_change_proposals` and backfills version 1, kind Converted, for every lesson with its tags and pictures):
  - `LessonVersion` (+ `LessonVersionTag`, `LessonVersionPicture`): kept permanently, numbered from 1 per lesson (unique `(lesson_id, number)`); kind Converted, ApprovedSuggestion, PublishedDirectly or ReplacedInFull; title, order, active, body, content version, suggester, approver or publisher, reason, link to its suggestion. Its pictures' blob keys are never overwritten (content-addressed keys), so every version stays readable.
  - `LessonSuggestion` (+ tags, pictures): Draft, Submitted, Approved or SentBack; kind Edit, ReplaceInFull, NewLesson or Retire; the base version; the sent-back comment and who decided; `RevisesSuggestionId` when an author carries on from one sent back. One open (Draft or Submitted) per lesson: checked in the service and by the filtered unique index `IX_lesson_suggestions_lesson_id_open` (`status IN (0, 1)`).
  - `LessonPublishingSettingChange`: the national "Direct publishing allowed" / "Review required" setting as an audit of changes; the latest row is the setting, none means allowed.
- **Roles, checked in the service**: suggest (create, save, submit, discard, upload a picture to one's own draft) Teacher or Approver (`SuggesterRoles`); review, approve (one's own included), send back with a comment, "Publish now" (only while direct publishing is allowed) Approver; history Approver or Admin (`HistoryRoles`); the setting National Administrator. Lessons and suggestions are national, as the library is: no chapter filter, and nothing here reads `DbsCheck` or `ConsentSensitiveDetails`.
- **Publishing** (approve or Publish now) adds the next version, updates the live `Lesson` (title, order, tags, body, live `LessonPicture` rows matched on file name, `IsActive = false` for Retire) and sets `ContentVersion` to a hash that includes the version number, so saved copies refresh. A new lesson gets the code `R<rank order>-<nn>`. A suggestion whose base is no longer the latest version cannot be approved, and a draft cannot be started from a version older than the latest (the editor sends the version it opened). Validation before submit or publish: title, order, a tag, text (not for Retire), every picture a bare file name in the suggestion with a description.
- **Committee referral and alerts** (decision 8, migration `AddLessonSuggestionCommitteeReferral`): `ReferAsync` sets `LessonSuggestion.ReferredAt`/`ReferredByUserId`/`ReferralReason` (submitted, current, unreferred only; status stays Submitted); `ApproveAsync` then refuses it and `ApproveReferredAsync` adds a `LessonSuggestionApproval` (unique per Approver and per position 1 to 3; a `DbUpdateException` from a simultaneous approval clears the change tracker and becomes "reload and try again") and publishes on the third, the version's `ApprovedByUserId` being the third Approver. Review, queue and history DTOs carry the `Referral` and `CommitteeApprovals` (`Pages/Lessons/CommitteeFacts.razor` in the history). `SubmitAsync` calls `LessonSuggestionNotificationService.NotifySubmittedAsync` (every Approver not left, via `INotificationService`, never throws); `NavMenu.razor` shows `CountAwaitingMyReviewAsync` as `.nav-count` plus visually hidden "(n awaiting review)". Tests: `LessonSuggestionCommitteeTests`.
- **Diff** (`LessonDiff`, DiffPlex 1.9.0, Apache-2.0): both sides rendered through `LessonMarkdown`, then a word-level diff of the HTML tokens, text wrapped in `<ins>`/`<del>`; pictures compared by blob key. Replace in full is shown side by side instead.
- **Seeder** (`CurriculumSeeder`, adr/0013 decision 9): records each lesson it creates or changes as its next Converted version; a lesson whose latest version did not come from the seeder is left untouched with a warning. Since adr/0015 the same rule covers a lesson's teacher's notes and a rank's Teacher's Information (see below).
- **Web**: `Pages/Lessons/LessonEditor.razor` (`/lessons/{Code}/suggest`, `/lessons/new/{RankCode}`, InteractiveServer, `RequireLessonSuggester`) hosts the vendored Toast UI Editor 3.2.2 (MIT, `wwwroot/lib/toastui-editor/`) through `wwwroot/lesson-editor.js`, which saves Markdown and swaps picture file names for addresses in and out; `Pages/Curriculum/ChangesToReview.razor` (`/curriculum/review`, nav "Changes to review", `RequireApprover`); `Pages/Curriculum/ReviewSuggestion.razor` (`/curriculum/review/{Id}`); `Pages/Lessons/LessonHistoryPage.razor` (`/lessons/{Code}/history`, `RequireLessonHistory`); the lesson page shows the version, "Suggest changes", "History" and the in-progress notice; the library has "New lesson" per rank; `Pages/Administration/LessonPublishingSettingPanel.razor` on the Chapters page. Endpoints in `LessonSuggestionEndpoints`: picture upload (antiforgery), a suggestion's pictures (author or Approver), a version's pictures (Approver or Admin).
- **Tests**: `LessonSuggestionServiceTests`, `LessonDiffTests`, `CurriculumSeederLessonTextTests` (versions, skip), `LessonSuggestionEndpointTests`, `Vlms.UiTests/LessonSuggestionJourneyTests`.

## Teacher's notes and editable Teacher's Information (FR-024 amended, `docs/adr/0015-teachers-notes-and-editable-teachers-information.md`)

- **Data** (migration `20261110135627_AddTeachersNotes`): `Lesson.TeachersNotes`, `LessonVersion.TeachersNotes`, `LessonSuggestion.TeachersNotes` (Markdown, null = none); `LessonPicture.TeachersNotesOnly` (a picture only the notes use; notes pictures share the lesson's picture rows and file-name namespace, no separate table); `TeachersInformationVersion` (+ `TeachersInformationVersionPicture`), numbered per rank like `LessonVersion`, kinds Converted, ApprovedSuggestion, PublishedDirectly or ReplacedInFull. No backfill: a rank's version 1 (Converted) is made by the seeder, or by `LessonSuggestionService` the first time someone suggests a change to Teacher's Information that has none.
- **Who sees it**: `LessonLibraryService.TeachersInformationRoles` = Teacher, Admin, National Administrator, Approver (`CanReadTeachersMaterial`). `GetLessonPageAsync` sets `ShowsTeachersMaterial`, `TeachersInformationHtml`, `TeachersNotesHtml` and `RankCode` only for those roles; the page's `Html` and `PictureIds` never include a notes-only picture. `OpenTeachersNotesPictureAsync(id)` (any picture of an active lesson, staff roles) serves the notes' pictures; `OpenPictureAsync` never serves a notes-only one. Notes pictures render at `/lessons/teachers-notes/pictures/{id}` when notes-only, otherwise at the ordinary picture address.
- **Lesson suggestions carry the notes**: `SuggestionInput.TeachersNotes`; review (`NotesTrackedHtml`/`NotesFinalHtml`/`NotesBeforeHtml`, always tracked, also for Replace in full), publishing (live pictures = text references then notes-only references; the version stores the notes; Retire keeps them) and history (`NotesChangesHtml`) cover both. The content version hash appends the notes only when there are any, so a lesson without notes keeps its hash.
- **Teacher's Information as its own suggestion type**: a `LessonSuggestion` with `Kind = TeachersInformation`, `LessonId` null, `RankId` set, title "Teacher's Information"; so the queue, review, committee referral and Approver alerts work unchanged. One open per rank (service, and filtered unique index `IX_lesson_suggestions_rank_id_teachers_information_open`, `kind = 4 AND status IN (0, 1)`); the stale-base guard uses the rank's latest Teacher's Information version. A suggestion cannot switch between Teacher's Information and a lesson. Publishing updates `Rank.TeachersInformation` and its `TeachersInformationPicture` rows and adds the next version. Methods: `GetTeachersInformationEditorAsync`, `GetTeachersInformationHistoryAsync` (Approver or Admin), `OpenTeachersInformationVersionPictureAsync`.
- **Seeder**: reads `lessons/<code>.notes.md` (no file = no notes; a notes file with no lesson text is a warning), pictures from the lesson's folder under the same rules and errors; notes and their pictures are part of the content version. Teacher's Information pictures are now content-addressed (`teachers-information/<rank code>/<16 hex>/<name>`) so versions stay readable; each change is recorded as the rank's next Converted version, and a rank whose latest version came from a suggestion is left untouched with a warning.
- **Web**: `LessonText.razor` shows staff a "Teacher's Information" `details` (always, empty state "No Teacher's Information yet." with a suggest link; "Suggest changes" and "History" links) and a "Teacher's notes" `details` (empty state "No teacher's notes yet." with the lesson's suggest link, or the disabled button while someone else's suggestion is open). `LessonEditor.razor` has a second editor ("Teacher's notes"; `lesson-editor.js` now keeps named editors, `text` and `notes`) and a third route `/curriculum/teachers-information/{rank}/suggest` (text editor only, no settings). `LessonHistoryPage.razor` also serves `/curriculum/teachers-information/{rank}/history`. Endpoints: `GET /lessons/teachers-notes/pictures/{id}` (`RequireTeachersInformation`), `GET /curriculum/teachers-information/versions/pictures/{id}` (history policy). The service worker also saves notes pictures, only after the signed-in user fetched them.
- **Tests**: `LessonPageServiceTests`, `LessonPageEndpointTests`, `TeachersNotesSuggestionTests`, `CurriculumSeederTeachersNotesTests`, `EndToEnd/TeachersNotesEndToEndTests` (rendered page and notes picture per role).

## Updating init-only domain entities

Entities use this codebase's init-only property convention (see [domain.md](domain.md)). Services change an existing row through the change tracker, `context.Entry(x).Property(p => p.Field).CurrentValue = value`, which EF Core writes through the backing fields.

## App-hosted lessons (FR-024, `docs/adr/0012-app-hosted-lessons.md`)

A converted lesson is text and pictures held by the app instead of a list of downloads. Unconverted lessons keep their files exactly as before.

- **Data** (migration `AddAppHostedLessons`): `Lesson.Body` (Markdown, null = not converted) and `Lesson.ContentVersion` (SHA-256 hex of the text and the original pictures' bytes, set by the seeder); `LessonPicture` (per lesson, unique by `FileName`, the name the text uses) and `TeachersInformationPicture` (per rank); `Rank.TeachersInformation` (Markdown). Pictures are kept apart from `LessonFile`, so the library's file list never touches them.
- **Import** (`CurriculumSeeder`, `Vlms.Jobs seed-curriculum`): `<content root>/lessons/<lesson code>.md`, pictures in `lessons/<lesson code>/`; a rank's Teacher's Information in `lessons/R<rank order>-TI.md` (or `<rank code>-TI.md`; both is an error), pictures in the folder of the same name. Validate-then-write as before: a picture reference that is not a bare file name, not JPEG/PNG, missing or unreadable is an error and nothing is written. Each picture is resized at import (`LessonPictureResizer`, SkiaSharp, MIT: at most 1,600 px on the long side, smaller ones kept byte for byte) and stored under `lesson-pictures/<code>/<16 hex of the original's SHA-256>/<name>` (content-addressed, so a lesson version's picture is never overwritten) or `teachers-information/<rank code>/<16 hex>/<name>` (content-addressed since adr/0015); picture rows are matched on file name, so ids are stable. A lesson's pictures are uploaded only when its content version changed or a blob is missing; a re-run with nothing changed writes nothing. A body in the database with no file is kept (warning); a `.md` matching no lesson and an unused picture are warnings.
- **Rendering** (`LessonMarkdown`, Markdig 1.4): pipe tables and emphasis extras, `DisableHtml()` so tags in the text are shown as text; links keep only http(s), mailto, tel, fragments and relative paths (others lose the link, keep the words) and get `rel="noopener"`; images resolve only through the caller's file-name map to `/lessons/pictures/{id}` (or `/lessons/teachers-information/pictures/{id}`), get `loading="lazy"`, and an unresolved image becomes its alt text. Tests: `LessonMarkdownTests`.
- **Reads** (`LessonLibraryService`): `GetLibraryAsync` (projected; `HasPage`, `ContentVersion`, `PictureIds` per lesson), `GetLessonPageAsync(code)` (null for unknown, retired or unconverted; the Teacher's Information HTML only for `TeachersInformationRoles` = Teacher, Admin, National Administrator and, since adr/0015, Approver, decided in the service), `OpenPictureAsync(id)` (library roles, active lessons), `OpenTeachersInformationPictureAsync(id)` (staff roles only). Tests: `LessonPageServiceTests` (each role).
- **Web**: page `Pages/Lessons/LessonText.razor` at `/lessons/{Code}` (static SSR, no interactive component, `RequireLessonLibrary`; staff see a `details` "Teacher's Information" at the top; print stylesheet in `app.css`); the library links a converted lesson's title to it. Both pages carry the shared `SaveLessonButton.razor` ("Save to this device"). Endpoints in `LessonPageEndpoint`: `GET /lessons/pictures/{id}` (library policy), `GET /lessons/teachers-information/pictures/{id}` (`RequireTeachersInformation`). There is no separate offline rendering (adr/0012 decision 7, amended 26/10/2026): the lesson page itself is saved; see [web.md](web.md). Tests: `LessonPageEndpointTests`, `Vlms.UiTests/LessonPageJourneyTests` (axe, 375 px, print, save from the page and read offline).
